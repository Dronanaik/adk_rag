    from google.adk.agents import LlmAgent
from app.rag_store import hybrid_search, vector_search
from app.graph_store import graph_search, get_entity_relationships

root_agent = LlmAgent(
    name="hybrid_rag_kg_agent",
    model="gemini-2.5-pro",
    instruction=build_agent_instruction,
    tools=[
        hybrid_search,
        vector_search,
        graph_search,
        get_entity_relationships,
    ],
)
    -- 70% pgvector HNSW Cosine + 30% PostgreSQL GIN Full-Text
SELECT chunk_id, filename, content,
       (0.7 * (1 - (embedding <=> %(query_vec)s::vector)) +
        0.3 * ts_rank_cd(
          to_tsvector('english', content),
          plainto_tsquery('english', %(query)s)
        )) AS combined_score
FROM document_chunks
WHERE user_id = %(user_id)s
ORDER BY combined_score DESC LIMIT 5;
    // Multi-Hop Tenant-Isolated Neo4j Knowledge Graph Traversal
MATCH (s:Entity {user_id: $user_id})
      -[r:RELATES_TO {user_id: $user_id}]->
      (t:Entity {user_id: $user_id})
WHERE toLower(s.name) CONTAINS $term
   OR toLower(r.fact) CONTAINS $term
RETURN s.name AS source, r.relation_type AS relation,
       t.name AS target, r.fact AS fact
LIMIT 15;

    Frequently Asked Questions

    Key architectural and operational answers about ADK Agentic RAG + Knowledge Graph:

    Why combine Neon pgvector Hybrid Search with a Neo4j Knowledge Graph?

    Vector similarity excels at conceptual semantics, and PostgreSQL Full-Text Search (ts_rank_cd) captures exact technical identifiers, acronyms, and SKUs. However, neither represents explicit multi-hop relationships across documents. By extracting structured (:Entity)-[:RELATES_TO]->(:Entity) triplets into Neo4j during ingestion and exposing all four tools to the Google ADK LlmAgent, the agent can combine local passage evidence with global graph topology in a single turn.

    How does the 5-step dual ingestion pipeline work in real time?

    When a user uploads a file via POST /upload, the backend updates an in-memory per-user stage tracker polled every 800ms by the React UI (GET /ingest/progress): (1) Document parsing (pypdf / python-docx / UTF-8), (2) Paragraph-aware chunking (1200 chars, 200 overlap), (3) Batched 768-dim embeddings via gemini-embedding-001, (4) Neon PostgreSQL document_chunks indexing (HNSW + GIN), and (5) Gemini 2.5 Flash structured entity/relationship extraction into Neo4j.

    How is multi-tenant data isolation enforced across Neon and Neo4j?

    Every user authenticates against the Neon PostgreSQL users table using PBKDF2-HMAC-SHA256 password hashing (120,000 iterations) and receives a signed HS256 JWT token. Every SQL query filters on WHERE user_id = %(user_id)s, every Neo4j node ID is namespace-prefixed (user_id::entity_name) with {user_id: $user_id} property filters, and ADK chat sessions are keyed by (app_name, user_id, session_id).

    How does the Google ADK LlmAgent decide which retrieval tool to call?

    The hybrid_rag_kg_agent is initialized with dynamic runtime instructions via build_agent_instruction(ReadonlyContext) and four function tools: hybrid_search (default for factual/technical queries), vector_search (for broad conceptual similarity), graph_search (for discovering entities and relationship facts), and get_entity_relationships (for 1-hop neighborhood inspection). Gemini 2.5 Pro autonomously invokes one or multiple tools before synthesizing a grounded response.

    What happens when a user deletes a document?

    Calling DELETE /documents/{document_id} performs an atomic cascade across both databases: it deletes the document and its document_chunks from Neon PostgreSQL, removes all [:RELATES_TO {document_id}] edges and the (:Document) node in Neo4j, and automatically prunes any orphaned (:Entity) nodes that no longer have any remaining relationships or document mentions.

    How do I deploy the platform to production?

    The backend deploys as a Python web service on Render (or Google Cloud Run) connected to serverless Neon PostgreSQL and Neo4j AuraDB, while the Vite + React frontend deploys to Netlify. Full configuration templates (render.yaml, netlify.toml) and environment variable checklists are provided in the Cloud Deployment Guide.
